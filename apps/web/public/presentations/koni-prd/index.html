Ringkasan Eksekutif
Slide 2

Alasan produk ini dibangun

  • KONI Kabupaten Malang mengelola ribuan atlet, puluhan cabor, dan event daerah yang sebelumnya tersebar secara manual.
  • Target utamanya adalah menghadirkan transparansi publik, efisiensi operasional, dan keputusan pembinaan berbasis data.
  • PRD membagi perjalanan produk ke empat fase agar migrasi dari MVP lama ke platform terintegrasi berjalan bertahap dan realistis.
Tujuan 1
Transparansi & Akuntabilitas
Portal resmi memberi akses publik ke profil organisasi, berita, event, dan capaian olahraga daerah.
Tujuan 2
Database Terpusat
Atlet, pelatih, dokumen, cabor, dan event dipindahkan ke model relasional yang bisa dikelola lintas peran.
Tujuan 3
Digitalisasi Event
Pendaftaran, jadwal, hasil, dan klasemen medali diarahkan ke alur digital yang bisa dipakai operator dan publik.
Tujuan 4
Fondasi Sport Science
Tahap akhir menyiapkan rekam fisik atlet dan e-proposal pembinaan sebagai basis program pembinaan modern.

Ringkasan Fase

  • Fase 1: portal publik, profil organisasi, direktori cabor, berita.
  • Fase 2: SIM internal berbasis PostgreSQL, RBAC, auth yang aman, E-SK.
  • Fase 3: manajemen event, entry peserta, live result, medal standings.
  • Fase 4: sport science, rekam fisik, e-proposal pembinaan.
    • Status proyek terkini tervalidasi

    Memory proyek pada 10 Maret 2026 mencatat portal publik, admin CMS, event, medal standing, dan baseline SIM internal sudah aktif di monorepo `apps/web` + `apps/api`.

    Konteks Bisnis
    Slide 3

    Latar belakang, stakeholder, dan pain point

    As-Is dari PRD

    • MVP awal sudah punya form pendaftaran, integrasi Google Drive/Sheets, dan dashboard admin dasar.
    • Namun model ini belum kuat untuk relasi data atlet, cabor, prestasi, dan event yang lebih kompleks.
    • Belum ada portal publik resmi, RBAC penuh, maupun alur event end-to-end.

    Stakeholder utama

    • Pengurus KONI: butuh dashboard terpusat dan laporan cepat.
    • Admin Cabor: ingin mengelola data cabornya tanpa proses manual ke sekretariat.
    • Atlet/Pelatih: butuh akses digital ke profil, dokumen, dan jadwal.
    • Publik/Pemerintah: butuh portal resmi yang mudah diakses.

    Value bisnis

    • Satu sumber data untuk operasional dan publikasi.
    • Mempercepat onboarding atlet, dokumentasi, dan koordinasi event.
    • Membuka jalan ke pembinaan berbasis data dan pengawasan kinerja program.

    Implikasi produk

    Karena kebutuhan publik dan internal sama-sama penting, arsitektur produk dibangun sebagai monorepo: `apps/web` untuk portal publik + admin, dan `apps/api` untuk backend Express/Prisma. Ini menjaga delivery bertahap tetap konsisten, tanpa memecah codebase terlalu dini.

    User Persona
    Slide 4

    Persona dan model akses yang dilayani sistem

    Super Admin
    Pengurus KONI
    Mengelola semua cabor, atlet, pelatih, berita, event, medal standings, dan approval dokumen organisasi.
    Admin Cabor
    Operator Mandiri Per-Cabor
    Akses terbatas ke cabornya sendiri untuk data atlet, pelatih, pendaftaran event, dan proposal pembinaan.
    Atlet / Pelatih
    Self-Service Terbatas
    Melihat dan memperbarui profil, dokumen, prestasi, serta nantinya rekam fisik dan jadwal pertandingan.
    Guest / Publik
    Akses Informasi Resmi
    Mengonsumsi berita, profil organisasi, direktori cabor, jadwal event, dan medal tally tanpa login.

    Realitas implementasi saat ini

    Berdasarkan memory proyek, role inti yang sudah dimodelkan di Prisma adalah SUPER_ADMIN, CABOR_ADMIN, COACH, dan ATHLETE. Fase 2 sudah memiliki login, refresh, logout, proteksi route, dan pembatasan delete atlet hanya untuk super admin sesuai baseline RBAC yang berjalan.

    Fase 1-2
    Slide 5

    Fitur fase 1 dan fase 2 yang sudah terlihat nyata

    Fase 1
    Portal Publik
    Homepage, profil, berita, direktori cabor, kontak, serta rendering event dan medal tally dari data API nyata.
    Fase 2
    SIM Internal
    Auth login/refresh/logout, dashboard statistik live, athlete CRUD, coach CRUD, news CMS, dan alur admin yang sudah aktif.
    Evidence sukses yang dipakai
    • Homepage memuat event mendatang dan klasemen medali dari API real.
    • Dashboard admin dan halaman manajemen atlet sudah data-driven.
    • Phase 2 verification script terakhir tercatat PASS untuk login, refresh, logout, health, public cabor, dan contact form.

    Snapshot di atas berasal dari retest PASS 9 Maret 2026 saat homepage menampilkan `PORKAB Kabupaten Malang 2026`, bar statistik, berita terbaru, dan section `Klasemen Medali`.

    Fase 3-4
    Slide 6

    Fase lanjutan: event management menuju sport science

    Fase 3
    Manajemen Event & Kejuaraan
    Pembuatan event, jadwal, pendaftaran peserta, hasil pertandingan, dan medal standings per event.
    Fase 4

    Snapshot PASS menunjukkan editor standings di admin berhasil menyimpan row medali untuk event uji, menandakan fondasi fase 3 sudah hidup di produk.

    Non-Fungsional & Desain
    Slide 7

    Standar kualitas dan arah UI/UX dari PRD

    Non-Fungsional

    • Page load target di bawah 3 detik pada koneksi 4G.
    • 95% API response di bawah 500ms.
    • Uptime target 99,5% per bulan.
    • JWT + Refresh Token, HTTPS wajib, backup harian.

    UI/UX

    • Palet utama: putih, KONI Gold, KONI Red, Dark Navy, Light Gray.
    • Gaya visual: modern, tegas, sedikit tajam, dengan kesan prestisius.
    • Mobile-first dan animasi halus untuk menjaga kesan institusional namun energik.
